\section{What you are measuring}
The a1975 experiment is a $^{16}$C beam ($\sim$192~MeV, $\sim$12~MeV/u) stopped in an
\textbf{H$_2$ gas active target} at 1~bar; the gas is \emph{both} the proton target and the
tracking medium. You will analyze the neutron-pickup reaction
\[
  ^{16}\mathrm{C} + p \;\rightarrow\; ^{15}\mathrm{C}^{*} + d ,
\]
i.e.\ $^{16}$C$(p,d)^{15}$C, by detecting the outgoing \textbf{deuteron}. From the deuteron's
kinetic energy $T_d$ and lab angle $\theta_{\mathrm{lab}}$ you reconstruct the $^{15}$C
excitation energy $E_x$ with two-body relativistic kinematics, and you study which $^{15}$C
states are populated versus angle.

\medskip
\noindent This guide goes \textbf{from scratch}: raw HDF5 $\to$ reconstruction $\to$ deuteron fit
$\to$ excitation-energy spectrum, using only the macros in this directory.

\section{Setup and data layout}
Run everything from the (p,d) macro directory after sourcing the framework environment:
\begin{lstlisting}[language=bash]
cd <ATTPCROOT>/macro/Unpack_HDF5/a1975/UKF
source <ATTPCROOT>/build/config.sh
\end{lstlisting}
Choose \emph{one} base directory for the data and export it; everything below refers to it as
\code{\$DATA}. Substitute your own path (e.g.\ on the analysis machine it is \code{/mnt/f/a1975}):
\begin{lstlisting}[language=bash]
export DATA=/path/to/a1975          # <-- set this to where your data lives
\end{lstlisting}
The expected layout under \code{\$DATA} is:
\begin{itemize}[nosep]
  \item \code{\$DATA/h5/}\hfill raw HDF5, one file per run: \code{run\_0106.h5}, \dots, \code{run\_0189.h5}
  \item \code{\$DATA/reco/}\hfill you will produce \code{*\_reco.root} here (and the experiment's \code{*\_FRIB.root} ion-chamber files live here)
  \item \code{\$DATA/reco\_pd/}\hfill your (p,d) fit outputs (\code{mkdir -p \$DATA/reco\_pd})
\end{itemize}
The macros are in \code{pp/} and \code{pipeline/}. Static macros write a PNG (open with your image
viewer); the interactive ones (\code{explore\_pd}, \code{pid\_gate\_edit}) need an X display, so run
them with \code{root -l} (no \code{-b}).

\paragraph{One path to set in the macro.} The reconstruction macro reads its raw input from a
directory defined near the top of \code{pipeline/unpackReco\_a1975\_UKF.C} (the line
\code{TString filepath = "..."}). Edit it once to point at \code{\$DATA/h5/}. Every later macro
takes its directories as \emph{arguments}, so you pass \code{\$DATA/...} directly.

\section{The pipeline}
\begin{center}
\code{\$DATA/h5} $\to$ \fbox{unpack + PSA + space-charge + PRA} $\to$ \code{\$DATA/reco/*\_reco.root}
$\to$ \fbox{deuteron genfit fit} $\to$ \code{\$DATA/reco\_pd/*\_genfitter\_pd.root}
$\to$ \fbox{cache} $\to$ \code{/tmp/pd\_kin.root} $\to$ \fbox{plots}
\end{center}
Pattern recognition (finding tracks) does not depend on the assumed particle, so one
reconstruction serves every channel; for (p,d) you then \emph{fit} the tracks as deuterons.

\section{Step 1 --- Reconstruct from raw data}
\code{unpackReco\_a1975\_UKF.C} runs the full chain (unpack $\to$ pulse-shape analysis $\to$
space-charge correction $\to$ pattern recognition) and writes one \code{*\_reco.root} per run
(containing the corrected hits and the found tracks \code{AtPatternEvent}). For one run:
\begin{lstlisting}[language=bash]
root -l -b -q 'pipeline/unpackReco_a1975_UKF.C("run_0106", -1, false, "'$DATA'/reco/")'
\end{lstlisting}
Arguments: \code{(run, nEvents=-1 for all, persistRaw, outDir)}. This is the slow stage; run the
whole experiment on 4 cores:
\begin{lstlisting}[language=bash]
ls $DATA/h5/run_*.h5 | grep -oE 'run_[0-9]+' | sort -u > /tmp/runs.txt
cat /tmp/runs.txt | xargs -P4 -I{} \
  root -l -b -q "pipeline/unpackReco_a1975_UKF.C(\"{}\", -1, false, \"$DATA/reco/\")"
\end{lstlisting}

\section{Step 2 --- Fit the deuterons}
\code{fitGenfitter\_a1975.C} reads a \code{*\_reco.root}, keeps only tracks inside the deuteron PID
band (\code{pid/deuteron\_band.json}), fits each as a deuteron with genfit, and writes the fitted
kinematics. Its defaults are already the deuteron hypothesis:
\begin{lstlisting}[language=bash]
cat /tmp/runs.txt | xargs -P4 -I{} \
  root -l -b -q "pipeline/fitGenfitter_a1975.C(\"{}\", -1, \"$DATA/reco/\", \"_pd\", \"$DATA/reco_pd/\")"
\end{lstlisting}
Arguments: \code{(run, nEvents, inputDir, outputSuffix, outputDir)}, output
\code{\$DATA/reco\_pd/run\_XXXX\_genfitter\_pd.root}. A deuteron is rare ($\sim$1.5\% of tracks), so
most events print \code{0/1 tracks fitted} --- that is the gate working, not an error. Expect
$\sim$30{,}000 deuterons over the 84 runs.

\section{Step 3 --- Cache the kinematics}
Cache just the per-deuteron numbers into a flat ntuple (also pulls the \textbf{ion-chamber} value
from the \code{*\_FRIB.root} files for a $^{16}$C beam gate):
\begin{lstlisting}[language=bash]
cat /tmp/runs.txt | xargs -P4 -I{} \
  root -b -q "pp/cache_pd_run.C(\"{}\",\"/tmp/pdkin_{}.root\",\"$DATA/reco_pd/\",\"$DATA/reco/\")"
hadd -f /tmp/pd_kin.root /tmp/pdkin_run_01*.root
\end{lstlisting}
This makes \code{/tmp/pd\_kin.root} (ntuple \code{pk}: \code{ke, theta, vz, chi2ndf, ic, run}).
All later plots read this single file, so they are fast.

\section{Step 4 --- The excitation-energy spectrum}
From $T_d$ and $\theta_{\mathrm{lab}}$ the macros compute $E_x(^{15}\mathrm{C})$ with two-body
kinematics. Make the 4-panel overview:
\begin{lstlisting}[language=bash]
root -l -b -q 'pp/plot_pd.C'                          # -> /tmp/pd_spectrum.png
\end{lstlisting}
You should see a sharp $^{15}$C ground-state peak near $E_x=0$, excited states ($\sim$3.10,
4.66~MeV), and the deuteron $T_d$-vs-$\theta_{\mathrm{lab}}$ band lying on the analytic kinematic
line. A $\chi^2/\mathrm{ndf}$ cut and the IC beam gate (950--1350) are applied by default.

\section{Step 5 --- Angular dependence}
A discrete state appears at the same $E_x$ at every angle, with an angle-dependent strength. Plot
$E_x$ in $\theta_{cm}$ slices:
\begin{lstlisting}[language=bash]
root -l -b -q 'pp/plot_pd_angbins.C(10,5,12)'         # start 10 deg, 5 deg wide, 12 bins
\end{lstlisting}
The ground-state resolution is best forward ($\sigma\approx0.15$~MeV at $20$--$30^\circ$).

\section{Step 6 --- Correct the $E_x$-vs-$\theta_{cm}$ drift (important!)}
The reconstructed ground state is not flat in $\theta_{cm}$ --- its centroid drifts by
$\sim$0.9~MeV, which smears the integrated spectrum. Measure and subtract that drift:
\begin{lstlisting}[language=bash]
root -l -b -q 'pp/excorr_pd.C'                        # -> /tmp/pd_excorr.png
\end{lstlisting}
Left: the measured drift and the curve subtracted. Right: integrated $^{15}$C spectrum before/after
--- the g.s.\ FWHM improves from $\sim$1.7~MeV to $\sim$0.43~MeV. This is the single most important
correction for the integrated spectrum; it is built into \code{plot\_pd\_angbins.C}
(arg \code{driftCorr}, on by default) and the explorer (a checkbox).

\section{Step 7 --- Beware triton contamination}
$^{16}$C$(p,t)^{14}$C makes \textbf{tritons}. The deuteron PID gate is loose enough to admit some,
and genfit fits a triton \emph{as a deuteron} with a good $\chi^2$, so you cannot remove them with
a $\chi^2$ or IC cut --- they form a faint second band above the deuteron locus. Inspect the PID
plane and tighten the gate:
\begin{lstlisting}[language=bash]
root -l -b -q "pp/pid_pd.C(106,113,\"$DATA/reco_pd/\")"     # sqrt(dE/dx) vs Brho + gate
root -l 'pp/pid_gate_edit.C'                                # draw a tighter gate, Save JSON, re-run Step 2
\end{lstlisting}
Species separation must come from the \textbf{gate}, not the fit.

\section{Step 8 --- Interactive exploration}
For tuning cuts/binning live (needs a display):
\begin{lstlisting}[language=bash]
root -l 'pp/explore_pd.C'
\end{lstlisting}
Controls: beam energy, $\chi^2/\mathrm{ndf}$, $\theta$ window, IC window, vertex-$z$ bounds, $E_x$
binning, and check-boxes for the drift correction and the $^{15}$C reference lines.

\section{Physics checklist}
\begin{itemize}[nosep]
  \item $^{15}$C g.s.\ ($1/2^+$) at $E_x=0$; first excited state 0.740~MeV ($5/2^+$, on the g.s.\ shoulder).
  \item Prominent strength near 3.10 and 4.66~MeV; broad structure at 6--8~MeV.
  \item The deuteron $T_d(\theta)$ band must follow the analytic g.s.\ kinematic line --- if not,
        suspect a wrong beam energy, $B$-field sign, or frame convention.
\end{itemize}

\section{Troubleshooting}
\begin{itemize}[nosep]
  \item \emph{``No raw/reco files found.''} Check \code{\$DATA} and the \code{filepath} line in the
        reconstruction macro.
  \item \emph{``\code{/tmp/pd\_kin.root} missing.''} \code{/tmp} clears on reboot --- rebuild the cache (Step~3).
  \item \emph{``Gate file not found.''} Run from the \code{UKF} directory so \code{pid/...json} resolves.
  \item \emph{``PID macro is slow.''} The IC gate reads the large FRIB files and is opt-in; without
        it, \code{pid\_pd.C} only reads the small PID branch and is fast.
  \item \emph{``GUI does not open.''} The interactive macros need X --- run with \code{root -l} (drop \code{-b}).
\end{itemize}
